# src-tauri (Rust/Tauri backend)

- `cargo check`/`cargo test` through the `rtk` hook can print a misleadingly terse summary (e.g. "cargo build (0 crates compiled)") that hides real errors/warnings — use `rtk proxy cargo <args>` when verifying changes. `Cargo.toml` lives here, not repo root — `cd src-tauri` first. The same hook can mangle plain `ls`/`grep` output on files under `target/` into truncated garbage — fall back to a Python file read if output looks wrong.
- Adding a new Tauri command needs `invoke_handler!` (`lib.rs`) AND `commands.allow` in the relevant `permissions/*.toml` (there's more than one, each scoped to a different window/capability — see `capabilities/*.json`) — guarded by `tests/command_registration.rs`, so `cargo test` catches a missed entry instead of a silent runtime "not allowed".
- Changing an existing Tauri command's signature: check BOTH call kinds — some commands are also called directly as plain Rust fns from other commands (e.g. `search_ffn` calls `fetch_ffn(...).await` directly, no `invoke`), not just from `src/lib/api.ts`/`invoke()`. A new `Option<T>` param needs the JS side to send `paramName: null` explicitly (omitting the key isn't safe — match the existing `category ?? null` convention), and the param's type needs `#[derive(serde::Deserialize)]` even if it's always `null` in practice. Guarded by `tests/command_args.rs`: the keys `src/lib/api.ts` sends must equal the command's non-injected parameter names (camelCased), both ways — a new/renamed param fails `cargo test` until `api.ts` matches. Only `api.ts` is scanned (the debug page's raw `invoke` is not), and it panics on an `invoke(` shape it can't read (e.g. a payload passed as a variable) rather than skipping it.
- Renaming/adding a field on a Rust struct sent to the frontend (any `#[derive(Serialize)]` in `queries.rs`/`db.rs`/`fetch.rs`) needs a matching edit in `src/lib/types.ts` (same interface name, camelCase field) — guarded by `tests/type_mirror.rs`, which fails `cargo test` on drift. Covers `Serialize` (Rust→TS) structs only; `StoryFilters` (`Deserialize`, TS→Rust) is deliberately excluded — see the test's own doc comment for why. The test scans `src/*.rs` for every `Serialize`-deriving type, so moving a struct between files is fine, but adding a new one fails until it's listed in either `MIRRORED_STRUCTS` (frontend reads it) or `UNMIRRORED_TYPES` (with the reason it never crosses).
- Cross-side drift fails `cargo test` via text-scan guards — adding a `stories` column needs it in both `UPSERT_*_STORY_SQL` consts in `db.rs` unless truly per-source (`upsert_sql_columns_cover_the_schema`). Fetch commands return their result directly (no result events): a new one returns a `*Fetched` struct from `dispatch.rs` and needs the matching `types.ts` interface (`type_mirror.rs`).
- After editing `permissions/*.toml`/`capabilities/*.json`, don't trust a fast "Finished" build — verify the change actually landed (e.g. grep `target/debug/build/app-*/out/capabilities.json`) before assuming it's applied.
- Before trusting a schema migration in `migrations.rs`, copy the real DB to scratch and check `PRAGMA integrity_check`/`PRAGMA foreign_key_check`/row counts against the copy — don't just trust the SQL in isolation. (Stays manual — ruled out for mechanization 2026-08-31: the mechanism is a fixture-DB migration test, and no instance of this class has happened yet; record the first one here.)
- rusqlite's `row.get("col_name")` needs an explicit `AS col_name` on every SQL expression (COALESCE, subqueries included) — bare `table.column` refs get a default name, but expressions don't. (Ruled out for mechanization 2026-08-31 for lack of a query-layer test harness; `queries.rs` has one now — in-memory `db::tests::memory_conn()` plus the seeded `list_stories` suite — so a new `StoryRow` query can get a test that runs it, which catches a missing `AS` at `cargo test` time.)
- Icons come from `src-tauri/icons/icon.svg` (the source of truth): regenerate with `bun run tauri icon src-tauri/icons/icon.svg`, then `/bin/rm -rf src-tauri/icons/android src-tauri/icons/ios src-tauri/icons/64x64.png` — the CLI emits mobile assets this desktop-only app doesn't ship.
- When merging near-identical branches during a dedup refactor, check each one for an invariant-enforcing `unreachable!()`/`assert` before collapsing them — it reads like duplication but silently dropping it removes a real safety check.
- `tokio` has only the `rt`+`sync`+`time` features: no `#[tokio::test]`/`join!`/`start_paused` — async tests build a `current_thread` runtime by hand, use `tokio::spawn` for a fake page report and short real timeouts (see `fetch_session.rs` tests and `fetch.rs`'s `FakeWebview`).
