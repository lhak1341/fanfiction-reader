# src-tauri (Rust/Tauri backend)

- `cargo check`/`cargo test` through the `rtk` hook can print a misleadingly terse summary (e.g. "cargo build (0 crates compiled)") that hides real errors/warnings — use `rtk proxy cargo <args>` when verifying changes. `Cargo.toml` lives here, not repo root — `cd src-tauri` first. The same hook can mangle plain `ls`/`grep` output on files under `target/` into truncated garbage — fall back to a Python file read if output looks wrong.
- Adding a new Tauri command needs `invoke_handler!` (`lib.rs`) AND `commands.allow` in the relevant `permissions/*.toml` (there's more than one, each scoped to a different window/capability — see `capabilities/*.json`) — guarded by `tests/command_registration.rs`, so `cargo test` catches a missed entry instead of a silent runtime "not allowed". If the command fn lives in a submodule (e.g. `fetch.rs`), `use module::fn_name;` it into `lib.rs` and list the bare name in `generate_handler!` — the test string-scans for bare identifiers, and `module::fn_name` won't match `permissions/*.toml`'s bare names.
- Changing an existing Tauri command's signature: check BOTH call kinds — some commands are also called directly as plain Rust fns from other commands (e.g. `search_ffn` calls `fetch_page(...).await` directly, no `invoke`), not just from `src/lib/api.ts`/`invoke()`. A new `Option<T>` param needs the JS side to send `paramName: null` explicitly (omitting the key isn't safe — match the existing `category ?? null` convention), and the param's type needs `#[derive(serde::Deserialize)]` even if it's always `null` in practice.
- Renaming/adding a field on a Rust struct sent to the frontend (any `#[derive(Serialize)]` in `queries.rs`/`db.rs`/`fetch.rs`) needs a matching edit in `src/lib/types.ts` (same interface name, camelCase field) — guarded by `tests/type_mirror.rs`, which fails `cargo test` on drift. Covers `Serialize` (Rust→TS) structs only; `StoryFilters` (`Deserialize`, TS→Rust) is deliberately excluded — see the test's own doc comment for why. Moving one of these structs to a different file also needs its `(file, struct_name)` entry updated in the test's `MIRRORED_STRUCTS` table, or it fails with a confusing "no struct X {} found" instead of a field-drift message.
- After editing `permissions/*.toml`/`capabilities/*.json`, don't trust a fast "Finished" build — verify the change actually landed (e.g. grep `target/debug/build/app-*/out/capabilities.json`) before assuming it's applied.
- Before trusting a schema migration in `db.rs`, copy the real DB to scratch and check `PRAGMA integrity_check`/`PRAGMA foreign_key_check`/row counts against the copy — don't just trust the SQL in isolation.
- rusqlite's `row.get("col_name")` needs an explicit `AS col_name` on every SQL expression (COALESCE, subqueries included) — bare `table.column` refs get a default name, but expressions don't.
- When merging near-identical branches during a dedup refactor, check each one for an invariant-enforcing `unreachable!()`/`assert` before collapsing them — it reads like duplication but silently dropping it removes a real safety check.
