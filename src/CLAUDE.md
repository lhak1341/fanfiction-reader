# src (React frontend on @lhak/style)

- Screen state lives in framework-free `Store` classes (`lib/store.ts`; `SearchScreen`, `BookmarksScreen`, `ReaderScreen`, `SearchModalScreen`, `ErrorBanner`). Assigning a field notifies React (`app/useStore.ts`), so replace arrays and Sets, never mutate them in place. A Screen owns its reactive rules inside `start()` as `this.watch([keys], run)` reactions (the explicit key list is the dependency list; a field missing from it never retriggers), stopped by `dispose()`; tests call `start()` then `flushSync()` (from `./store`) after assigning a field. Only state no single Screen owns (view mode, navigation, the Reader pause rule) belongs in `app/App.tsx`.
- UI is kit components from `@lhak/style/react` first; app CSS (`app.css`) uses only `--lk-` roles, and the app's own layout values take `--fanf-`. Kit CSS shares one cascade with `app.css`: never set an inherited property on a bare element selector.
- The kit's `ThemeSwitch` sits in the Appearance popover (`app/AppearanceMenu.tsx`), never directly in a toolbar.
- `src/routes/debug/+page.svelte` (unported until style-guide ticket 13) deliberately uses raw `invoke()` for commands, not `api.ts`-style command wrappers (the one `api.fetchChapterAndWait` call, for bulk prefetch, is the exception) — it's a debug harness for exercising Tauri commands directly, don't fold command dispatch into shared seams during a refactor. Pure non-command utilities (e.g. `pacedLoop.ts`'s `jitterDelay`/`sleep`) are fine to share.
- A `*Screen` class that starts background work (a prefetch chain, a polling loop) needs a `dispose()` that bumps its generation token, called from the owning component's effect cleanup — nothing else stops it on unmount (`ReaderScreen` kept prefetching after Back until this was added).
- Failures shown on the page banner go through `ErrorBanner` (`lib/errorBanner.ts`), one message per operation key: `banner.run(key, prefix, op)` for anything that throws (clears on success; `{ clearOn: "start" }` for bulk jobs), `banner.report(key, text)` for a job's partial failure. Only the same key succeeding, or the user's Dismiss, removes a message — so no ordering rule about `reloadAll()`. A new banner-reporting operation needs a new `BannerKey`; tests assert on `banner.messages`, not a callback.
- The strict CSP (`src-tauri/tauri.conf.json`) carries `@lhak/style`'s `STYLE_HASHES`; `lib/cspStyleHashes.test.ts` checks it. It applies only in `tauri build`, never `tauri dev`. Per the CSP spec, inline `style="…"` attributes in parsed HTML (chapter markup) are blocked under it while CSSOM writes from React are not; inferred, not yet probed in the app.
