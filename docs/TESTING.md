# Testing conventions

- `vitest run` swallows `console.log` — pass `--reporter=verbose --silent=false` to see it when debugging a failing test.
- vitest runs in a plain Node environment (`vitest.config.ts`, via `vitest.client-env.ts`, which makes Vite compile runes for the browser so `$effect` runs) with no `--localstorage-file` — `localStorage` is genuinely `undefined` in every test, and no DOM (`DOMParser`/`TreeWalker`/etc.) exists either. Code behind a `typeof localStorage === "undefined"` guard silently no-ops/returns default; to actually test the read/write logic, stub it first (`vi.stubGlobal("localStorage", fakeImpl)` in `beforeEach`/`vi.unstubAllGlobals()` after). To test real DOM-walking code, opt that one file into `jsdom` (already a devDependency) with a `// @vitest-environment jsdom` docblock, as `src/lib/typography.dom.test.ts` does — don't flip the global environment, it'd risk breaking tests elsewhere that rely on the node-only undefined-`localStorage` behavior above.
- A `.test.ts` can `import` a JSON fixture from anywhere in the repo (e.g. `src-tauri/tests/fixtures/*.json`) directly — `resolveJsonModule` is already on, no vite config needed. Combined with Rust's `include_str!(concat!(env!("CARGO_MANIFEST_DIR"), "/tests/fixtures/..."))`, this is the pattern for keeping two independently-written same-concept adapters (one per language, e.g. accent-folding) provably in sync.
- Building a fixture with composed-vs-decomposed Unicode pairs (e.g. accent-folding tests): generate via `python3 -c 'import unicodedata; ...'` and `assert` the two forms differ, rather than hand-typing/escaping combining marks — a transcription slip there silently invalidates the test.
- Fake-timer tests of a jittered loop (`pacedLoop.ts`) must pin `Math.random` (`vi.spyOn(Math, "random").mockReturnValue(0)`, then `vi.restoreAllMocks()`) — otherwise elapsed-time arithmetic depends on the random draw and the test is flaky.
