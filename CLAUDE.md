# Longform (FanFiction Reader)

- DB lives at `~/Library/Application Support/com.lhak1341.longform/longform.db` — safe to inspect/edit directly with `sqlite3` while `bun run tauri dev` is running.
- `docs/SPEC.md` is the living spec — read the relevant section before touching scraping/fetch/data-model code, and update it when behavior changes.
- Live-fetch verification (confirming scraping behavior against FFN/AO3) must use `python3 urllib`, not `curl` — blocked by sandbox policy. AO3 origin is flaky (timeouts, `HTTP 525`) even when not bot-blocked — retry 3-4x before concluding a fetch failed. FFN itself is fully Cloudflare-blocked (403) for *any* bare client, `urllib` included, even with a real desktop UA header — there's no way around this without the app's own webview.
- To capture real FFN markup for a fixture/test: trigger the fetch in the running app (`bun run tauri dev`), then copy `~/Library/Application Support/com.lhak1341.longform/debug-last-fetch.html` (or `debug-last-ao3-fetch.html` for AO3) *before* the next fetch overwrites it — this file always holds the most recently fetched page's raw HTML.
- `cargo check`/`cargo test` through the `rtk` hook can print a misleadingly terse summary (e.g. "cargo build (0 crates compiled)") that hides real errors/warnings — use `rtk proxy cargo <args>` when verifying Rust changes in `src-tauri`. The same hook can also mangle plain `ls`/`grep` output on files under `target/` into truncated garbage — fall back to a Python file read if output looks wrong.
- Before trusting a schema migration in `db.rs`, copy the real DB to scratch and check `PRAGMA integrity_check`/`PRAGMA foreign_key_check`/row counts against the copy — don't just trust the SQL in isolation.
- Adding a new Tauri command needs `invoke_handler!` (`lib.rs`) AND `commands.allow` in the relevant `permissions/*.toml` (there's more than one, each scoped to a different window/capability — see `capabilities/*.json`) — guarded by `src-tauri/tests/command_registration.rs`, so `cargo test` now catches a missed entry instead of a silent runtime "not allowed".
- After editing `permissions/*.toml`/`capabilities/*.json`, don't trust a fast "Finished" build — verify the change actually landed (e.g. grep `target/debug/build/app-*/out/capabilities.json`) before assuming it's applied.
- Background `bun run tauri dev`/vite processes are invisible to `ps aux` from the Bash tool but hold real ports/locks — use `lsof -i :1420` / `lsof +D src-tauri/target` to find and kill them, not `ps`.
- `timeout` isn't available in this shell (macOS, no coreutils) — use `run_in_background` + manual sleep/check instead.
- This app can't be screenshot-verified via Playwright/chromium-cli or a plain browser hit to the Vite dev server — Tauri's native WKWebView isn't CDP-attachable, and `window.__TAURI__` (so any `invoke()` call, so any real data) doesn't exist outside the actual app shell. For UI changes, ask the user to check the running `bun run tauri dev` app directly instead of attempting an automated screenshot.
