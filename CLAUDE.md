# Longform (FanFiction Reader)

- DB lives at `~/Library/Application Support/com.lhak1341.longform/longform.db` — safe to inspect/edit directly with `sqlite3` while `bun run tauri dev` is running.
- `docs/SPEC.md` is the living spec — read the relevant section before touching scraping/fetch/data-model code, and update it when behavior changes.
- No `docs/adr/` in this repo — architectural decisions live in `docs/wayfinder/map.md` + `docs/wayfinder/tickets/*.md` (macro) and inline `// architecture review candidate N` comments across `src/lib`/`src-tauri/src` (micro, per-module) — grep `architecture review candidate` before proposing a refactor to avoid re-litigating a settled one.
- `temp/` (repo root, gitignored) is this project's scratch/output dir — architecture-review reports and similar throwaway outputs belong there, not OS tmp.
- Live-fetch verification (confirming scraping behavior against FFN/AO3) must use `python3 urllib`, not `curl` — blocked by sandbox policy. AO3 origin is flaky (timeouts, `HTTP 525`) even when not bot-blocked — retry 3-4x before concluding a fetch failed. FFN itself is fully Cloudflare-blocked (403) for *any* bare client, `urllib` included, even with a real desktop UA header — there's no way around this without the app's own webview. To verify or backfill a specific parsed field against real data, run the actual Rust parser against saved live HTML via a throwaway `#[test]` (`--nocapture`) rather than hand-deriving the value — it's the ground truth and won't have a transcription bug.
- To capture real FFN markup for a fixture/test: trigger the fetch in the running app (`bun run tauri dev`), then copy `~/Library/Application Support/com.lhak1341.longform/debug-last-fetch.html` (or `debug-last-ao3-fetch.html` for AO3) *before* the next fetch overwrites it — this file always holds the most recently fetched page's raw HTML.
- `cargo check`/`cargo test` through the `rtk` hook can print a misleadingly terse summary (e.g. "cargo build (0 crates compiled)") that hides real errors/warnings — use `rtk proxy cargo <args>` when verifying Rust changes in `src-tauri`. Cargo.toml lives at `src-tauri/Cargo.toml`, not repo root — `cd src-tauri` first, don't assume cwd carried over from an earlier command. The same hook can also mangle plain `ls`/`grep` output on files under `target/` into truncated garbage — fall back to a Python file read if output looks wrong.
- Before trusting a schema migration in `db.rs`, copy the real DB to scratch and check `PRAGMA integrity_check`/`PRAGMA foreign_key_check`/row counts against the copy — don't just trust the SQL in isolation.
- Adding a new Tauri command needs `invoke_handler!` (`lib.rs`) AND `commands.allow` in the relevant `permissions/*.toml` (there's more than one, each scoped to a different window/capability — see `capabilities/*.json`) — guarded by `src-tauri/tests/command_registration.rs`, so `cargo test` now catches a missed entry instead of a silent runtime "not allowed".
- Renaming/adding a field on a Rust struct sent to the frontend (any `#[derive(Serialize)]` in `queries.rs`/`db.rs`/`lib.rs`) needs a matching edit in `src/lib/types.ts` (same interface name, camelCase field) — guarded by `src-tauri/tests/type_mirror.rs`, which fails `cargo test` on drift. Covers `Serialize` (Rust→TS) structs only; `StoryFilters` (`Deserialize`, TS→Rust) is deliberately excluded — see the test's own doc comment for why.
- After editing `permissions/*.toml`/`capabilities/*.json`, don't trust a fast "Finished" build — verify the change actually landed (e.g. grep `target/debug/build/app-*/out/capabilities.json`) before assuming it's applied.
- Background `bun run tauri dev`/vite processes are invisible to `ps aux` from the Bash tool but hold real ports/locks — use `lsof -i :1420` / `lsof +D src-tauri/target` to find and kill them, not `ps`.
- `timeout` isn't available in this shell (macOS, no coreutils) — use `run_in_background` + manual sleep/check instead.
- This app can't be screenshot-verified via Playwright/chromium-cli or a plain browser hit to the Vite dev server — Tauri's native WKWebView isn't CDP-attachable, and `window.__TAURI__` (so any `invoke()` call, so any real data) doesn't exist outside the actual app shell. For UI changes, ask the user to check the running `bun run tauri dev` app directly instead of attempting an automated screenshot.
- Svelte 5 `$derived` class fields never invalidate outside a live component/effect-root context — a bare `new SearchScreen()`-style instance in a vitest test computes it once and never recomputes. Use a plain getter instead when a value derived from `$state` fields needs to work both inside `$effect` and from a bare test instantiation.
- Svelte scoped `<style>` never reaches markup rendered by a child component — when extracting a shared block (e.g. a button row) into its own `.svelte` file, move its CSS into that new component too, don't leave it in the parent's stylesheet.
- When merging near-identical branches during a dedup refactor, check each one for an invariant-enforcing `unreachable!()`/`assert` before collapsing them — it reads like duplication but silently dropping it removes a real safety check.
- rusqlite's `row.get("col_name")` needs an explicit `AS col_name` on every SQL expression (COALESCE, subqueries included) — bare `table.column` refs get a default name, but expressions don't.
- `vitest run` swallows `console.log` — pass `--reporter=verbose --silent=false` to see it when debugging a failing test.
- vitest runs in a plain Node environment (`vitest.config.ts`) with no `--localstorage-file` — `localStorage` is genuinely `undefined` in every test. Code behind a `typeof localStorage === "undefined"` guard silently no-ops/returns default; to actually test the read/write logic, stub it first (`vi.stubGlobal("localStorage", fakeImpl)` in `beforeEach`/`vi.unstubAllGlobals()` after).
- Testing a function that takes Tauri `listen()`-shaped callbacks as plain params (dependency-injected, not imported): fake them with a `.then()`-resolving stub returning an `unlisten` mock, and flush one microtask (`await Promise.resolve()`) before firing a simulated event — mirrors real Tauri ordering, where `listen()`'s registration promise always resolves before an event can arrive on that channel.
- Svelte 5 warns `state_referenced_locally` when a `$props()` value is passed as a one-shot constructor/call argument (e.g. `new XScreen(storyId, ...)`) — not when read inside a function body. The `*Screen` classes (`SearchScreen`/`BookmarksScreen`/`ReaderScreen`/`SearchModalScreen`) hit this every time; if the prop genuinely can't change during that mount (confirm via how the parent conditionally mounts it), silence with `// svelte-ignore state_referenced_locally` + a one-line why, don't restructure to chase the warning away.
- `src/routes/debug/+page.svelte` deliberately uses raw `invoke()` for commands, not `api.ts`-style command wrappers — it's a debug harness for exercising Tauri commands directly, don't fold command dispatch into shared seams during a refactor. Pure non-command utilities (e.g. `pacedLoop.ts`'s `jitterDelay`/`sleep`) are fine to share.
- A `.test.ts` can `import` a JSON fixture from anywhere in the repo (e.g. `src-tauri/tests/fixtures/*.json`) directly — `resolveJsonModule` is already on, no vite config needed. Combined with Rust's `include_str!(concat!(env!("CARGO_MANIFEST_DIR"), "/tests/fixtures/..."))`, this is the pattern for keeping two independently-written same-concept adapters (one per language, e.g. accent-folding) provably in sync.
- Building a fixture with composed-vs-decomposed Unicode pairs (e.g. accent-folding tests): generate via `python3 -c 'import unicodedata; ...'` and `assert` the two forms differ, rather than hand-typing/escaping combining marks — a transcription slip there silently invalidates the test.
